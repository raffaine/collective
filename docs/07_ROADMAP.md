# Roadmap: The Oasis-to-Collective Pipeline

The greatest barrier to a decentralized, sovereign society is not technological; it is psychological and logistical. You cannot ask a neighborhood reliant on Amazon and municipal grids to suddenly adopt a 7-layer cryptographic permaculture stack. The friction is too high.

**Oasis is the Trojan Horse.** 

We build a C++20, Vulkan-rendered voxel survival simulation. To the public, Oasis is an incredibly deep, systemic game about escaping legacy collapse and building a resilient eco-village. But under the hood, it is a deterministic Level of Detail (LoD) simulator, a BPMN 2.0 visualizer, and a JSON-LD schema generator. 

When a player successfully designs a zero-waste water loop or a localized 3D-printing mesh in the game, the engine generates the exact cryptographic schemas required to run that system in reality. As the player base scales, Oasis quietly transitions from a video game into the digital twin operating system for **The Collective**.

---

## The Four Phases of Manifestation

### Phase 1: The Voxel Crucible (Software Synthesis)
*Build the standalone digital simulator. Establish the core C++20 engine, WASM compilation, and headless physics validation without any real-world IoT tethers.*

*   **Engine Core:** Data-Oriented Design (DOD) voxel memory layout, Vulkan compute shaders for thermodynamics (water, heat, exergy), and WebAssembly (WASM) local browser execution.
*   **Orchestration Integration:** Embed the BPMN 2.0 XML parser. Players use the UI to automate in-game tasks (e.g., routing water).
*   **Scenario Testing:** Implement the 24 Alpha-Omega scenarios as the core gameplay loop. Players must survive the "August Desiccation" and "Legacy HOA Assault" using only Sovereign Stack mechanics.

### Phase 2: The Meatspace API (Hardware Bridging)
*Puncture the digital barrier. Oasis begins reading and actuating the physical world via Layer 2 MQTT brokers.*

*   **The Sensor Bridge:** Players can bind real-world IoT sensors to their in-game voxels. A real capacitive soil sensor in a backyard garden dictates the moisture state of the player's in-game permaculture chunk.
*   **The Actuator Bridge:** In-game BPMN workflows begin triggering real-world hardware. 
*   **Fabrication Commons Pilot:** Connecting physical Bambu A1 Mini networks to the in-game Layer 6 Intent queues, allowing players to order real physical prints through the game's UI.

### Phase 3: Genesis Node Duvall (Physical Bootstrapping)
*The game manifests its first localized physical hub in Cascadia. Oasis is no longer just a game; it is the dashboard for a real neighborhood.*

*   **Layer 7 Activation:** Establish the Perpetual Purpose Trust (PPT) and Social Purpose Corporation (SPC) to secure the physical land and shield the node from legacy municipal friction.
*   **Trojan Services Launch:** Roll out the "Commons Kitchen" and "Mutual Aid Childcare" (Scenarios Gamma & Delta). Oasis handles the Layer 5 Trust Rings and Layer 3 Value Token ledgers for the local citizens.
*   **Proof of Stewardship:** The first Value Tokens are minted based on real, mathematically verified negentropy (solar surplus, harvested biochar).

### Phase 4: The Gossipsub Mesh (Global Federation)
*The Genesis Node scales peer-to-peer. The centralized concept of a "Game Studio" dissolves entirely into The Collective.*

*   **Node Federation:** Genesis Nodes across different bioregions connect via libp2p Gossipsub.
*   **The Epistemic Mesh:** R&D and agricultural data (Scenario Iota) are cryptographically shared across the global network, allowing the system to learn and adapt without legacy universities.
*   **Terminal Decoupling:** Oasis effectively becomes the localized OS. Sovereign communities can indefinitely sustain their caloric, thermodynamic, and social needs even if the legacy grid experiences total failure (Scenario Omega).

## Strategic Imperatives for the AI-Human Studio

To execute Phase 1 without collapsing under technical debt, our development loops must be ruthlessly disciplined:

1.  **Engine First, UI Last:** We do not waste cycles painting the UI until the headless C++20 chunk manager can successfully simulate fluid decay on a $32^3$ voxel grid in WebAssembly.
2.  **Strict Scenario Boundaries:** If a feature does not directly solve one of the 24 scenarios (Alpha-Omega), it is cut. We are not building endless sandbox features; we are building a survival simulator against entropy.
3.  **Schemas as Code:** The JSON-LD and BPMN outputs of the game must be perfectly compliant with real-world W3C standards from day one. Oasis is a compiler; its output must be executable by real machines.
