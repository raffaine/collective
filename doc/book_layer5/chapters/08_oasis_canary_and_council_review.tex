Governance protocols are notoriously easy to romanticize in whitepapers and notoriously brittle
when exposed to everyday physical friction. A threshold-signature ceremony that omits
duplicate-signer checks silently allows self-dealing; a trust-attenuation JSON file serialized

unauthenticated administrative backdoor around the entire democratic process; and a static
workflow table built for four tutorial tasks collapses when a living neighborhood node scales to
hundreds of concurrent agroforestry, culinary, childcare, and microgrid state machines.

Throughout the maturation of the Sovereign Stack, \textbf{Oasis (\texttt{Layer 1b})}---our
3D low-poly diorama and deterministic Software-in-the-Loop (SITL) proving ground instantiated on
reference parcel \textbf{Lot~402}---has served as the honest mirror in which Layer~5's
governance abstractions meet running C++20 silicon. This closing chapter of Part~I bridges the
formal theory of Chapters~\ref{ch:l5-bilateral-membrane}--\ref{ch:l5-sanctuary-justice} with
the live codebase as it stands today. First, we establish the constitutional airgap between
Oasis (\texttt{Layer 1b}) and physical dwellings (\texttt{Layer 1a}). Second, we tour
\textbf{seven working Layer~5 highlights} already executing end-to-end across
\texttt{col-kmsd}, \texttt{SharedStackRuntime}, \texttt{col-gatewayd}, \texttt{col-swarmd}, and
\texttt{col-execd}. Third, we present the complete findings of the \textbf{Five-Specialist
Layer~5 Architectural Council Audit}, diagnosing \textbf{eight concrete runtime ceilings} in
the current prototype---with exact file paths, line numbers, and struct layouts---paired with
ratified v3.1 fixed-point C++20 remedies. Finally, we chart the four-milestone engineering
roadmap that elevates \texttt{col-kmsd} from its Lot~402 seed into full multi-thousand-workflow
watershed sovereignty.
